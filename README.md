# samarthya.me

A personal portal: a running, public record of things built, learned and tried, at work and in spare time.
Long-form technical write-ups live in **Posts**; short notes about a single day live in **Daily**.

The site started on WordPress in 2019 and was rebuilt in 2026 as a static [Hugo](https://gohugo.io/) site
with the [Blowfish](https://blowfish.page/) theme, published by GitHub Pages. Every old URL still redirects
to its new home.

---

## How the site is organised

| Path | What it holds |
|---|---|
| `content/posts/<slug>/index.md` | Technical posts. One folder per post; its images sit next to `index.md`. |
| `content/daily/YYYY-MM-DD-title.md` | Daily entries: short, one file each. |
| `content/topics/` | Topic pages, generated automatically (see below). Nothing to edit here. |
| `content/_index.md` | Homepage words: intro, story and milestones. |
| `data/covers.yaml` | Topics: name, colours, symbol and the keywords that place a post in a topic. |
| `data/featured.yaml` | The homepage "Trophy shelf": a short, hand-picked list of posts. |
| `layouts/` | Small project-level template overrides (homepage, topics, card images). The theme itself is untouched. |
| `assets/css/custom.css` | Project styles on top of the theme. |
| `assets/img/covers/` | Topic cover images, generated by `tools/covers/make_covers.py`. |
| `static/` | Favicons and other files served as-is. |
| `themes/blowfish/` | The theme, as a git submodule. Not edited. |
| `tools/wp2hugo/` | One-off importer used for the WordPress migration. |

### What updates by itself

On every build, Hugo recomputes all of this from the content, so a new post shows up without any extra step:

- the homepage **"Sneak peek"** grid, **Posts** and **Daily** lists, tags, search and RSS
- the counters and the **"Writing over the years"** chart
- **Topics**: each post is placed in the first topic in `data/covers.yaml` whose keywords match one of its
  tags, categories or title words. Topic pages, counts and the coloured strip on each post follow.
- the card image: the post's first image, or `featureimage:` from its front matter, or else the topic cover

What stays manual: the **Trophy shelf** (`data/featured.yaml`) and the homepage **milestones** (`content/_index.md`).

## Writing

Prerequisites: [mise](https://mise.jdx.dev/) (pins the Hugo version from `mise.toml`) and git.
```sh
git clone --recurse-submodules https://github.com/samarthya/blog.samarthya.me.git
cd blog.samarthya.me
mise install
```

### A new post
```sh
mise exec -- hugo new posts/my-topic-name/index.md
```
1. Fill in `title`, a one-line `description`, and `tags`. Reuse existing tags (`k8s`, `golang`, `docker`,
   `elasticsearch`, `linux`, ...) so the post lands in the right topic.
2. Put images in the same folder and reference them by file name: `![What the image shows](diagram.png)`.
   Always write the alt text; it is what screen readers announce.
3. Give code blocks a language for highlighting: ```` ```go ````, ```` ```yaml ````, ```` ```bash ````.

### A daily entry
```sh
mise exec -- hugo new daily/2026-10-25-short-title.md
```
A few lines are enough: what was done, and why it counts.

### Preview, then publish
```sh
mise exec -- hugo server -D     # http://localhost:1313, includes drafts
```
Set `draft: false` when it is ready, then commit and push to `main`. The GitHub Actions workflow in
`.github/workflows/hugo.yml` builds the site and deploys it to GitHub Pages in about a minute.

Before pushing, the same build the CI runs should finish without errors:
```sh
mise exec -- hugo --gc --minify
```

### Photos and galleries
- Keep photos to roughly 2000 px wide and a few hundred KB (JPG or WebP); GitHub Pages limits sites to 1 GB.
- **Strip location and personal metadata (EXIF) from phone photos before committing**: the repository is public.
- For a few related pictures inside a post, use the theme's gallery shortcode:
  ```
  {{</* gallery */>}}
    <img src="photo-1.jpg" alt="Describe the photo" class="grid-w50" />
    <img src="photo-2.jpg" alt="Describe the photo" class="grid-w50" />
  {{</* /gallery */>}}
  ```

### Shortcodes worth knowing
`lead` (a larger opening line), `alert` (a callout), `tabs`/`tab`, `steps`/`step`, `accordion`, `gallery`.
Full list: <https://blowfish.page/docs/shortcodes/>.

## Topics and covers

Add or change a topic in `data/covers.yaml` (name, label, symbol, two colours, keywords), then regenerate
the cover images:
```sh
python tools/covers/make_covers.py      # needs PyYAML and Pillow
```
A new topic page appears at `/topics/<name>/` on the next build.

## Old links

Posts imported from WordPress carry `aliases:` in their front matter, so every
`/wps/YYYY/MM/DD/slug/` address redirects to `/posts/slug/`. Keep those lines when editing an old post.
